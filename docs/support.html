1. First steps

Club Wallet has five tabs: Members, Design, Wallets, Email and Settings.

  1. Want to look around first? Settings → Load sample club fills the app with a made-up club. It replaces your data, so do it before setting up your own club.
  2. Import your member list (section 2).
  3. Design the card (section 3).
  4. Set up Apple Wallet, Google Wallet and email – once (sections 4–6). You can switch either wallet off if you don't need it.
  5. Make and send the cards (section 7).
Already using Club Wallet Cards on a computer (Ubuntu)? Choose File → Export for iPhone app… there, send the .clubwallet file to your iPhone, then tap it in the Files app (or Settings → Import from Ubuntu app). Everything – settings, keys, logo, background, members and photos – is copied in one go.

2. Members

The member list

Make a spreadsheet with one row per member and a header row. Save it as .ods, .xlsx or .csv and put it in Files (iCloud Drive or On My iPhone).

  • Required columns: Reg number, Name, Surname, email
  • Optional: Photo (a photo file name), Blood type (or Krvna grupa) and Rh (+/-, pos/neg or Rh+)

Columns are recognised by their names (English, Croatian and Serbian names work), in any order. Then: Members → ⋯ → Import member list…. Members with a missing or invalid email are shown in red.

Member photos

  • Tap a member → Choose photo to pick one from your photo library, or
  • Design → Import photos from Files… to add many at once. They're matched by file name: 1.jpg, 001.png, Name Surname.jpg, Surname_Name.png, 1_Name_Surname.jpg or email@address.jpg (capitals and č/ć/š/đ/ž don't matter).

Photos are cropped and turned upright automatically. Members without a photo still get a card.

Blood type and Rh

If your list has these columns, they appear on the card with a red drop. On a member's page, two switches show or hide each one on that member's card. In Select mode, the red drop button changes several members at once. Design → Show blood type and Rh on cards switches them off for everyone.

3. Card design

  • Card: club name, card title, season, and an optional expiry date (YYYY-MM-DD).
  • Colours: background, text and label colours – or Take colours from background picture.
  • Pictures: logo and background picture from your photo library or Files. Colour tint over picture at 0% shows the picture as it is; more tint makes text easier to read.
  • QR code content: what the QR code holds. Placeholders: {reg} {name} {surname} {full_name} {email} {club} {season} {blood_type} {rh}.
  • Preview shows the card picture (used in the email) and the Apple Wallet banner.

Apple Wallet layouts (Wallets → Layout):

  • Banner – the background picture as a sharp banner with the member's photo. Member name, Reg. No. and blood type underneath.
  • Full background – the picture fills the pass; iPhones always show it blurred. Photo as a thumbnail.
  • Classic – plain colour, photo as a thumbnail.

4. Apple Wallet (one-time setup)

Apple only accepts passes signed with the club's own certificate. You need an Apple Developer Program membership.

Easiest: with the computer app

Club Wallet Cards for Ubuntu has an automatic setup (club-wallet-cards-apple-setup) that creates everything. Then use Export for iPhone app… to bring it to your iPhone.

By hand

  1. On developer.apple.com → Identifiers → Pass Type IDs, create an ID like pass.com.yourclub.member.
  2. Create its certificate there. You need a certificate request (CSR); the Ubuntu app's Create key + CSR makes one, or Keychain Access on a Mac. Download pass.cer.
  3. Download Apple's intermediate certificate AppleWWDRCAG4.cer.
  4. In the app: Wallets → Certificate. Choose .cer + .pem key and import pass.cer and the private key, or choose .p12 file, import it and type its password. Also import the WWDR certificate.
  5. Tap Check certificate. The Pass Type ID and Team ID are filled in for you.

The certificate is valid for one year. Renew it a few weeks before it expires.

5. Google Wallet (one-time setup, free)

  1. In the Google Pay & Wallet Console, open Google Wallet API and create an issuer account.
  2. In Google Cloud, create a project, enable the Google Wallet API and create a service account with a JSON key. The Ubuntu app's club-wallet-cards-google-setup does this for you.
  3. In the Wallet Console → Users, invite the service account's email address as Developer.
  4. In the app: Wallets → Service account key → import the JSON file, then Find my Issuer ID and Test connection.

New issuer accounts start in demo mode: passes show "[TEST ONLY]" and only test users can save them. Request publishing access in the Wallet Console before sending to everyone. Google Wallet cards can only be saved on Android phones. To show a picture on the Google card, put a public https link to it in Banner URL (and Logo URL).

6. Email

  1. Email → Use Gmail settings (server smtp.gmail.com, port 465, SSL/TLS) – or enter your provider's SSL/TLS server.
  2. Username: your email address. Password: for Gmail, an App password (it needs 2-Step Verification). Your normal password won't work.
  3. Fill in the sender name and email, then write the subject and message. Placeholders: {name} {surname} {full_name} {reg} {email} {club} {season} {pass_filename}.
  4. Tap Send test email to myself and open it on your iPhone.

Port 587 (STARTTLS) is not supported – use port 465. Gmail sends at most about 500 emails a day.

7. Making and sending cards

  • One member: tap them, then Add to Apple Wallet on this iPhone (to check the card), Open Google Wallet link, or Email card to member.
  • Several: Select, tick the members, then Make (cards only) or Email.
  • Everyone: ⋯ → Email cards to everyone… When some members were already emailed, you can send only to the others.

Each email has the Apple Wallet pass (members tap it on an iPhone), an Add to Google Wallet button (Android) and a picture of the card. Cards are also saved in the Files app → On My iPhone → Club Wallet → Cards. Keep the app open while sending.

Changed the design or a member's data? Make and email the cards again – members get an updated card.

8. Problems?

  • "Certificate problem" / pass won't open: check the WWDR certificate, that the private key belongs to the certificate, and that the certificate hasn't expired (Check certificate).
  • Google: 401/403: the service account isn't invited in the Wallet Console yet, or the Google Wallet API isn't enabled.
  • Google card says [TEST ONLY]: your issuer account is still in demo mode – request publishing access.
  • Mail server error 535: wrong password – for Gmail use an App password.
  • Background not visible: lower Colour tint over picture, and use the Banner layout for Apple Wallet.
